# Заметки

Только то, чего не видно в коде. Всё остальное читается из исходников.

## Карта

- `src/lib/server/*` — домен на `neverthrow`: возвращает `Result`, не бросает.
  `HttpError` — только на границе (`unwrap` для UI, `runOp`/тул для MCP).
- `src/lib/remote/*` — операции; `registry.ts` — единственный источник и для UI,
  и для `/mcp`. Операция вне реестра в MCP не существует.
- Старт: `hooks.server.ts` → `getDb()` → `migrateDatabase()` → `ensureInbox()` →
  `startBackupScheduler()`.
- Импорты — `#lib/...`, не `$lib`.
- **Адрес задачи — `/tasks/project/{projectId}/{taskId}`**, проекта —
  `/tasks/project/{projectId}` (так же `/kanban`, `/activity`, `/deleted`).
  Активный проект читается из pathname, а не из `?project`; `/tasks/{taskId}` —
  короткий алиас для markdown, канонический путь достраивает `+layout.svelte`.
  Открытая задача — это URL, а не состояние: `selection` выводится из pathname,
  задача догружается через `pin`. `/` → 307 `/tasks`.

## Данные

- **ID задачи — `PREFIX-NUMBER`**, меняется при переносе. `moveTask` —
  единственное место, где переписывается `id`; поддерево эпика едет целиком,
  `scope_id` сбрасывается. Номера не переиспользуются
  (`task_number_high_water`), soft-deleted номер держит.
- **Префикс проекта** — верхний регистр, уникален без учёта регистра;
  уникальность держат триггеры (`UNIQUE` в SQLite регистрозависим).
- **Беспроектных задач нет**: `project_id NOT NULL`, служебный `inbox` (`INB`)
  создаёт `ensureInbox`, архивировать нельзя.
- **Резолв id** — только полный `PREFIX-NUMBER`, без учёта регистра. Голый номер
  отвергается (уникален лишь внутри проекта). Эпик обязан быть эпиком того же
  проекта.
- **`projects.repo`** — провенанс, не ключ: канон `host/owner/name`, без схемы,
  userinfo и `.git`, хост в нижнем регистре, сравнение `COLLATE NOCASE`. Не
  UNIQUE, у `inbox` пусто.
- **`activity.client`** — самоназвание клиента, не аутентификация; легаси и UI
  дают `null`, решения по нему не принимаются.
- **Блокеры**: блокер может быть из чужого проекта; self-блок и циклы
  отвергаются, повтор — no-op. Статус `blocked` ставится руками. Закрытие
  блокера снимает статус (в `blocked_from_status`, иначе `open`), но связь
  остаётся: она и есть история ожидания. `tasks_remove_blocker` — только для
  ошибочной связи. `blocked_reason` — одна строка, только у `blocked`.

## Свежесть

- Remote query кешируется по паре «функция + payload»: повторный вызов отдаёт
  значение из кеша, свежее — только через `refresh()` (или `query.live`).
  `fetchFresh` — единственная обёртка для «перезапросить и прочитать».
- Каналы обновления: `runOp` публикует `publishChange` для command,
  `/api/events` отдаёт SSE, реестр `createFreshness` в `board.svelte.ts` раздаёт
  перезагрузки. `live.ts` сторов не знает.
- `invalidate` локально буквальна; зависимости раскрывает только SSE: tasks →
  projects/scopes/tags/counters, projects → tasks/counters, scopes/tags → tasks.
  Локальная мутация обновляет лишь счётчики, список задач правится на месте и
  догоняется своим событием.
- Склейка — 300 мс. Событие несёт `source` и id вкладки (`x-xboct-client`):
  вкладка, сделавшая правку, своё событие пропускает, чужие применяет. Каскад
  той же команды (например, автоснятие `blocked`) поэтому не перечитывается —
  его добирает следующий `sync`.
- Таймаутов и ретраев у remote-функций нет: обёртка `hooks.client.ts` даёт
  `/remote/` таймаут 8 с, query — два ретрая, command — одну попытку (мутации не
  повторяются). `EventSource` переподключается сам, обёртка его не видит.

## Скоупы и теги

- **Скоупы включаются неявно**: режим активен, если у проекта есть хоть один
  скоуп. «Без скоупа» — `scope_id IS NULL`, удаление скоупа задачи не трогает.
  Скоуп необязателен, предупреждений не даёт.
- **Теги — закрытый словарь и m2m**: `task_tags` с FK на `tasks.id`
  (`ON DELETE CASCADE`) и `tags.name` (`ON UPDATE CASCADE`). Переименование —
  один `UPDATE`, удаление задачи чистит связи. Наружу — массив строк по
  алфавиту.
- Имя тега — только ASCII `a-z0-9_-`, до 20 символов, начинается с буквы или
  цифры. Неизвестный тег отвергается, архивный — только через восстановление,
  новый заводится явно (`tags_create`). Пустой набор — норма.

## Прод

- Артефакт вне git, служба NSSM `xboct-log`, порт `45881`, `HOST=0.0.0.0`, без
  аутентификации. Прод-пути — только в `scripts/deploy.ps1`; после правок путей:
  `git grep -n -E "xboct-log|build-wt|nssm"`.
- Деплой — `pnpm run deploy` (не `pnpm deploy`). Скрипт собирает локальный
  `HEAD` — непушнутый коммит едет в прод, незакоммиченные правки нет. `-Origin`
  собирает `origin/main` вместо `HEAD`. Работа в постоянном worktree, без `.env`
  в нём скрипт падает до касания прода.
- Серверные переменные `static: true` вшиваются в сборку: менять их на сервере
  бессмысленно, нужна пересборка. Миграции в проде идут на старте,
  `scripts/migrate.mjs` — только dev (ходит в `XBOCT_LOG_DEV_DB`).
- `adapter-node` без `PROTOCOL_HEADER` считает схему `https` и отбивает не-GET
  (403). `scripts/start-prod.mjs` выставляет `PROTOCOL_HEADER=x-forwarded-proto`
  до импорта `handler.js`; без этого работают только query.
- Прод-`node_modules` — только runtime: `neverthrow`, `zod`,
  `@ku6epxboctuk/sqlite-up`, `mcp-handler` (+ peer
  `@modelcontextprotocol/server`).
- Node ≥ 22.5 из-за `node:sqlite`; Bun не подходит.

## Бэкапы

- Виды: `auto`, `daily`, `weekly`, `manual`, у каждого своя папка и prune.
- **Автоснимок** — в `runOp` до обработчика, только для MCP: фиксирует состояние
  до правки. Ошибка не блокирует (fail-open), троттлинг — in-memory + mtime.
- **Восстановление** — страница `/backups`: проверяет снимок (заголовок,
  `integrity_check`, `schema_migrations`, отказ на неизвестные миграции из более
  новой версии), гоняет миграции на копии `.new`, пока живая БД работает,
  сохраняет текущее состояние в `manual/` и подменяет файл в синхронном блоке
  `closeDb()` → rename → `getDb()`. Клиент присылает только `kind`+`name`, путь
  берётся из `listBackups()`. После успеха уходит событие `reset`, и все вкладки
  перезагружаются. Через MCP восстановления нет сознательно.
  `scripts/restore.mjs` остаётся для случая, когда сервер не поднимается.
- Тесты пишут в `.dev/test-backups`, иначе дефолт указывает на прод.
- Старый снимок на новом коде безопасен (миграции догонят), обратное — нет.
  Легаси-имена тегов вне `a-z0-9_-` миграции 020–021 переименовывают (`est:L` →
  `est-l`, `ui\ux` → `ui-ux`), а не теряют.

## Разработка

- `pnpm dev` всегда идёт в `.dev/dev.db`, игнорируя `XBOCT_LOG_DB`, и уводит
  бэкапы в `.dev/backups`. `pnpm dev:vite` без изоляции, требует `XBOCT_LOG_DB`.
- `pnpm dev:seed` кладёт снимок из `.dev/seed/` в `.dev/dev.db`; прод не
  читается, снимок кладёт человек.
- У `XBOCT_LOG_DB` нет дефолта: без неё сборка и сервер падают.

## Расширение VS Code

- `vscode-extension/` — `WebviewPanel` с `<iframe>` на прод-URL, только
  `127.0.0.1`/`localhost`: из `vscode-webview://` http-iframe разрешён лишь для
  potentially-trustworthy origin, LAN-IP падает как mixed content.
- Тема не наследуется (кросс-доменный iframe): `?theme=` и `postMessage` при
  смене.
- `retainContextWhenHidden: true` обязателен, иначе переключение вкладки
  перезагружает SPA.

## MCP

- `/mcp` — Streamable HTTP в том же процессе. Токена нет сознательно: эндпоинт
  открыт как весь прод, токен дал бы ложное чувство защиты. Изоляция — правило
  Windows Firewall на нужную подсеть.
