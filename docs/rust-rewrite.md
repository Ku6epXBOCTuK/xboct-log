# Переписывание бэкенда на Rust

Бэкенд переписан как **точный порт**: внешняя граница и файл базы те же, что у
node-версии. Изменения поведения, схемы и контрактов — только отдельными задачами
после переезда.

Решения:

1. Фронтенд работает с REST, типы берутся из OpenAPI, сгенерированного Rust.
2. Доступ к БД — `sqlx`, `ULOWER` регистрируется на коннекциях через сырой хендл,
   схема базы не меняется.
3. Деплой — только Windows-инстансы (NSSM и portable).

## Правила работы

1. Тип существует ровно в одном месте — в Rust. В TypeScript попадает только
   сгенерированное, руками написанных DTO и путей API нет.
2. Всё, что можно вывести из исходников (схемы, роуты, описания инструментов,
   события), выводится из них, а не дублируется.
3. Идиоматичный код: newtype'ы вместо сырых `String`/`i64`, `thiserror`-enum
   вместо строковых ошибок, владение без `clone()` ради компилятора.
4. Если паритет и идиоматичность конфликтуют — выигрывает паритет, расхождение
   уходит задачей в XBOCT-log с файлом и способом увидеть разницу.
5. Отхождения от rust-way собраны в эпике `LOG-312`; эпик разбирается после
   перевода Rust в продакшен.

## Крейты

```txt
crates/core     домен, newtype'ы, ошибки, DTO, sqlx-репозитории, миграции,
                медиа, бэкапы, ретенция, планировщик
crates/ops      реестр операций: имя, вид, вход, выход, обработчик
crates/server   axum, REST, SSE, MCP, OpenAPI, отдача SPA с диска
crates/cli      лаунчер и админ-команды
```

`core` не знает про axum и MCP. Трейты только там, где нужна подмена в тестах
(`Clock`, `BlobStore`); репозитории — функции над `&SqlitePool`.

Newtype'ы: `TaskId`, `TaskKey`, `ProjectId`, `ScopeId`, `AttachmentId`, `Prefix`,
`TagName`, `Seq`. Enum'ы с `rename_all = "kebab-case"`: `Status`, `Priority`,
`ClosedReason`, `Estimate`, `EntityKind`, `ActivitySource`, `AppErrorKind`.

## Операции

Один трейт описывает имя, вид, вход, выход и обработчик. Из списка `ops![]`
генерируются REST-маршруты `POST /api/<name>`, MCP-инструменты, запись
активности и выбор SSE-сущности. Добавление операции — одна строка, HTTP и MCP
не могут разъехаться.

## Типы для фронтенда

```txt
core/ops DTO  ──▶  openapi.json  ──openapi-typescript──▶  src/lib/api/schema.d.ts
                                                          └─▶ openapi-fetch
```

- `src/lib/api/client.ts` — `openapi-fetch`, таймаут 8 с, заголовок
  `x-xboct-client`, `ApiError {status, kind, message}`, повтор только при
  сетевом сбое.
- `src/lib/api/*.ts` повторяют имена прежних remote-функций, поэтому сторы и
  компоненты не переписаны.
- Дрейф ловится `pnpm contract:check`: перегенерация и `git diff --exit-code`.

## База

`sqlx` с SQLite-пулом, на каждой коннекции `journal_mode=WAL`,
`foreign_keys=ON`, `busy_timeout`. Транзакции — `BEGIN IMMEDIATE` через guard
`Tx`, иначе параллельная запись даёт `SQLITE_BUSY_SNAPSHOT` там, где node ждал.

`ULOWER` живёт в одном модуле `core::db::ulower`, регистрируется в
`after_connect` каждой коннекции и повторяет node дословно. SQL с `ULOWER`
перенесён без изменений, новых колонок и производных таблиц нет. `unsafe` есть
только в этом модуле, остальные крейты под `#![forbid(unsafe_code)]`.

Миграции: одна `0001_init.sql` с финальной схемой node и 26 именами в
`schema_migrations`; своя история — в `_sqlx_migrations`. Node-база без
`_sqlx_migrations` помечается применённой по контрольной сумме файла; история от
старой сборки с другой суммой пересоздаётся. Пока поддерживается откат на node,
миграции Rust только аддитивные.

## Сделано

- Паритет-харнесс и снапшоты, `cargo test --workspace`, спеки node портированы.
- REST-слой, OpenAPI, `schema.d.ts`, клиент и обёртки; сторы и SSE не менялись.
- SPA отдаётся Rust с диска: `--web`, `XBOCT_LOG_WEB_DIR`, fallback на
  `index.html`.
- E2E: MCP-набор на 60 проверок и UI-набор на 10 сценариев.
- Сверка с node v0.9.0: UI 10/10 у обеих версий, у 51 общего MCP-инструмента
  схемы и описания совпадают.
- Чистая база создаёт `inbox` с префиксом `INB`, как node; `tasks_move` в него
  проходит.
- Ошибки валидации MCP совпадают с node: отсутствующее обязательное поле и
  неверный enum дают `unknown` и текст вида `Input validation error: ...`,
  как у Zod.
- Все E2E и `compare` идут на свежем снимке прод-базы; устаревшая
  `_sqlx_migrations` пересоздаётся при старте, данные не трогаются.
- Релиз собирает Rust: `XBOCT_LOG_STATIC=1 pnpm build` даёт SPA в `build`,
  `cargo build --release --locked -p xboct-log-cli` — `xboct-log.exe`;
  `scripts/package-win.ps1` кладёт их в zip и установщик. Node-бандл не пакуется,
  серверные маршруты `src/routes` (`api`, `mcp`, `media`) остаются в репозитории
  ради отката уже развёрнутых инстансов.

## Осталось

1. **Выкатка на Rust.** Служба запускает `xboct-log.exe` напрямую, лаунчера и
   Node на хосте больше нет. Переключение инстанса — решение владельца.

## E2E

| Команда                                                  | Что проверяет                                                                                                                              |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `pnpm e2e:mcp`                                           | все 53 инструмента, оба ресурса, ошибки; каждый инструмент из `tools/list` вызван                                                          |
| `pnpm e2e:ui`                                            | 10 сценариев на Rust: поиск, создание, закрытие/открытие, фильтры, сортировка, вложения, удаление/восстановление, проект, теги, активность |
| `pnpm exec playwright test -c playwright.node.config.ts` | те же 10 сценариев на node v0.9.0 из worktree `.dev/node-v0.9.0`                                                                           |
| `node scripts/e2e/compare.mjs`                           | все 53 инструмента MCP на одинаковой копии базы: схемы, поведение, ошибки                                                                  |

Все наборы берут свежий снимок прод-базы: `pnpm seed:prod` кладёт его в
`.dev/seed`, а скрипты копируют последний снимок в свои временные каталоги
(`--db=<path>` или `E2E_SEED_DB` задают файл явно). Устаревшую
`_sqlx_migrations` Rust чинит при старте сам. `pnpm e2e` запускает MCP и UI
подряд. Порты сдвигаются через `E2E_MCP_PORT`, `E2E_RUST_PORT`,
`E2E_NODE_PORT`; `E2E_KEEP=1` оставляет данные для разбора. Kanban не
проверяется: страница не сделана (LOG-207).

## Выкатка на прод и неделя наблюдения

1. `pnpm seed:prod`, затем `pnpm e2e` — прогон на свежем снимке прод-базы.
2. Одноразово владелец переводит службу на `xboct-log.exe`: сохраняет текущие
   `Application`/`AppDirectory`/`AppParameters`, меняет их через `nssm set`,
   проверяет health и отпечаток папки данных. Скрипт для этого живёт рядом с
   файлами инстансов, вне репозитория: он меняет конфигурацию службы, а не файлы
   проекта. После этого Node на хосте не нужен.
3. `pnpm deploy:rust <name>` — без прав администратора: бэкап, статическая сборка,
   копия exe и `web\`, health-gate. Папка, данные и порт читаются из `nssm get`,
   поэтому в файле инстанса остаётся только `SERVICE`.
4. Сразу после переключения: `/api/health`, 53 инструмента в `tools/list`, UI,
   SSE, вложения.
5. Неделя: логи сервиса, ответы 5xx, бэкапы, память. Косметика вроде LOG-319
   собирается, но не чинится на ходу.
6. Откат: прежние `Application`/`AppDirectory`/`AppParameters` возвращаются тем
   же одноразовым скриптом (они сохранены рядом с файлами инстансов); node-скрипты
   при нужде восстанавливаются из тега, где node-деплой ещё был.
7. Node и Rust не могут одновременно слушать один порт; порт и папка данных у
   каждого инстанса свои.

## План фиксов

Открытых расхождений паритета нет: `node scripts/e2e/compare.mjs` показывает
только осознанное расхождение ниже.

Осознанное расхождение: `activity.client` и `tasks_history` в Rust содержат имя
MCP-клиента из `initialize`, node v0.9.0 писал `null`, потому что `mcp-handler`
не передавал `clientInfo`. Контракт допускает имя клиента, поэтому Rust оставлен
как есть (LOG-323, `wontfix`).

LOG-319 (`tags_create` без человекочитаемой метки в активности) — косметика,
унаследованная от node; отложена до недели наблюдения.## Риски

- `move`/`renumber` и авто-закрытие эпика — главный источник расхождений.
- Тексты strict-ошибок и инструкции MCP должны совпадать дословно, иначе
  настроенные клиенты увидят разницу.
- `unsafe` в `ULOWER`: неверная сигнатура колбэка даёт UB; модуль один, покрыт
  тестами.
- `lock_handle` — деталь `sqlx`, мажорный апдейт проверяется первым.
- Пока node и Rust живут одновременно, правка node требует такой же правки в
  Rust.

## Оценка

Осталось около 5 рабочих дней: переключение сборки — 0.5, деплой и откат — 2,
прогон на копии прода — 2.
